### Fixes
- Fix database path override bug in `_SESSIONS_PATCH_SNIPPET`: line 2911 of `ui/server.py` hardcoded `DEFAULT_DB_PATH` instead of using the resolved `db` variable read from `BALABOT_CONTINUITY_DB`, causing `PATCH /api/sessions/{session_id}` to fail with 404 or corrupt split databases under custom continuity DB configurations.
- Prevent event loop blocking during container execution in `_org_run`: long-running container snippets in `_org_run` previously ran synchronously via `subprocess.run` inside `async def` FastAPI route handlers (`/api/org/secrets`, `/api/groups/{gid}/turn`, `/api/sessions`), locking the asyncio event loop and freezing concurrent user requests and streaming SSE sessions; route handlers now dispatch via non-blocking `_org_run_async` using `asyncio.to_thread` while preserving synchronous compatibility for existing test fixtures and callers.
- Enforce 10 MiB bounded uploads and ingest image attachments as multimodal vision objects: `/api/attachments` previously accepted unbounded upload streams into memory risking server denial-of-service, and `/api/chat` formatted attachments as plaintext filename strings so vision models never received image data; uploads now enforce `ATTACHMENT_MAX_BYTES` (10 MiB limit, returning 413 on oversized uploads) with ReDoS-safe decoding, and image attachments (`image/png`, `image/jpeg`, `image/webp`, `image/gif`) are converted to OpenAI-standard multimodal `image_url` content objects in chat payloads.
- Encrypt secrets at rest with AES-256-GCM, discontinue shell environment variable injection, and add server-side `secret_request` proxy tool: secrets were previously stored in plaintext on disk and injected into the bot's shell environment as raw environment variables where prompt injection or `env` could exfiltrate them; secret values are now authenticated and encrypted at rest with record binding (`BALABOT_SECRETS_KEY` / `master.key`), legacy plaintext secrets are transparently encrypted in place on read/migration, raw environment injection is eliminated, and agents access external credentials via the server-side `secret_request` proxy with origin allowlist validation, SSRF blocking, redirect refusal, credential response redaction, and an audit trail.
- Persist intervention records and frames in durable SQLite store and block in `request_intervention`: intervention state and frames were previously kept in ephemeral in-memory dictionaries that were lost upon CLI subprocess exit without pausing the agent turn; records and frames now persist to SQLite (`BALABOT_INTERVENTIONS_DB`), `/api/interventions` reads durable state, and `request_intervention` blocks in a polling wait-loop until human resolution or timeout.
- Enable Agent Computer endpoints for dynamic fleet bots: `/api/computer/{bot_id}/frame`, `/action`, and `/reset` previously validated against hardcoded `PROFILES = ["principal", "governor"]`, returning an unavailable error for user-created bots; they now validate against the dynamic fleet helper `_all_bot_meta()` shared across the server.
- Inject queued in-flight messages into upstream chat completions payload in `/api/chat`: messages enqueued during active turns were drained into SSE frames but omitted from `messages` sent to the model, dropping user input sent while an agent was busy.
- Update `ThinkingBlock` and `ThinkingOrb` components to dynamically track active theme mode rather than pinning dark styling.
- Remove the seeded demo conversation from `ui/src/sessions.ts`: a hardcoded "hire a marketing and SEO expert" exchange with a fabricated OpenUI card appeared in every install with an empty session store. An empty store now yields an empty roster — a conversation exists only because an agent or the owner actually had one.
- Correct the OpenUI approve handler's error path in `ui/src/App.tsx`, which reported `Proposal created: <error>` — success wording on a failure.
- Make the Astryx theme's token pairs genuinely mode-aware in `ui/src/theme.ts`: every `[light, dark]` pair previously held the dark value in both slots, so Astryx-styled components stayed near-black in light mode while the CSS layer switched. Light entries now mirror the `light-dark()` values already declared in `balabot.css`, reconciling the two theme systems.
- Replace five references to undefined CSS custom properties in `ui/src/App.tsx` and `ui/src/Composer.tsx` (`--surface-default`, `--border-default` ×2, `--surface-sunken` ×2). Each silently fell back to a hardcoded dark value, which painted the transcript header bar solid black and washed out the composer and textarea surfaces once light mode could be reached; they now use the real `--card`, `--border`, and `--muted` tokens.
- Require an explicit chat confirmation before an agent files a bot proposal: `personas/principal/AGENTS.md` and `personas/governor/AGENTS.md` previously instructed agents to file immediately, which is why a request to hire an agent produced a proposal with no name, role or confirmation settled in the conversation.
