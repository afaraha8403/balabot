### Fixes
- Harden secret proxy audit logging (Gap 1): stop recording raw URLs in `_record_secret_audit` (`balabot/bot_tools.py`), persisting only auditor-essential fields (timestamp, bot, secret_name, origin, method, status, reason, response_status) so query strings, tokens, and sensitive path identifiers never leak onto agent-accessible volumes.
- Eliminate DNS rebinding TOCTOU vulnerability in secret proxy (Gap 2): pin `httpx` HTTP connections to the single pre-validated IP via `_PinnedSyncBackend` and `_make_pinned_transport` in `balabot/bot_tools.py` while preserving the original Host header and TLS SNI for certificate verification; perform post-connect peer address verification to reject hostile DNS rebinding targeting loopback, private, or prohibited networks.
- Implement atomic master key rotation and disaster recovery for encrypted secrets (Gap 3): add `rotate_master_key`, `backup_secrets`, and `verify_secrets_integrity` in `balabot/orgs.py` and CLI (`python -m balabot.orgs rotate-key | backup | verify`); re-encrypts stored secrets atomically via a staging swap after creating a pre-rotation backup; embeds key identifiers in versioned envelopes (`BALABOT_ENC_V2:<key_id>:`) distinguishable from legacy V1 blobs; documents recovery story: the master key lives at `<data_root>/.secrets/master.key` (or `BALABOT_SECRETS_KEY`), a lost key renders stored secrets unrecoverable due to AES-256-GCM authenticated encryption, and the system continues to boot and operate gracefully when the secrets store cannot be decrypted.
- Enforce SQLite Write-Ahead Logging (WAL) journal mode across all durable product stores (Gap 4): configure `PRAGMA journal_mode = WAL` on open in `balabot.sessions.SessionStore` (`continuity.db`), `balabot.handoffs` (`handoffs.db`), `balabot.intervention` (`interventions.db`), and in `ui/server.py` session maintenance snippets, resolving concurrent reader/writer lock starvation and crash durability hazards on transcript stores; verify the three `balabot-jev` plugin stores (`/opt/data/memory/balabot-jev/continuity.db`, `/opt/data/profiles/principal/memory/balabot-jev/continuity.db`, `/opt/data/profiles/governor/memory/balabot-jev/continuity.db`) are directly owned by this repository via `hermes/plugins/balabot-jev/checkpoint.py:load_sessions_store` and automatically transition to WAL mode via `SessionStore`; add online backup (`conn.backup`) and integrity verification (`PRAGMA integrity_check`) methods and CLI commands (`backup`, `verify`) with documented restore drills across all durable stores.
- Enforce SQLite WAL journal mode at rest across all product stores via boot sweep (Gap 4b): add idempotent `sweep_wal_mode` and `get_product_store_paths` in `balabot.sessions` and invoke them at container startup in `balabot.bootstrap` (`run_bootstrap`); sweeps all product stores (`sessions/continuity.db`, `sessions/queue.db`, `handoffs/handoffs.db`, `interventions/interventions.db`, and `balabot-jev` plugin stores across root and persona profile homes) to apply `PRAGMA journal_mode = WAL` and normalize file ownership to `hermes`; safely tolerates absent or unexercised files and busy/locked databases, ensuring acceptance suites (`tests/e2e/bridge_api_e2e.py` W8-6 and `tests/e2e/bridge_shell_e2e.sh` W2-9) pass immediately after boot without first exercising each store.
- Decouple conversation transcript persistence from Jev availability: `_jev_prepare` in `ui/server.py` returned early whenever the Jev client was unavailable, silently skipping the session-store append so the user's message was never written to the durable transcript (the P1-2 real-path test passed only in a keyed shell and failed in a keyless/hermetic one); the turn's user message, resume state, topic span, and gate-admitted decisions are now written by a shared `_persist_turn_state` helper that both the Jev-present and Jev-absent paths call, and the AST wiring guard in `tests/test_jev_wiring_callsites.py` now asserts the append is reachable from `_jev_prepare` and that `_persist_turn_state` makes the direct store call.
- Add graceful heuristic fallback mode for TypeSafe AI Jev boot gate: `entrypoint.sh` and `balabot/jev.py` previously aborted container startup with exit code 1 whenever `TYPESAFE_API_KEY` was unset, blocking developers and self-hosters while direct API keys remain waitlisted; setting `JEV_MODE=heuristic` now bypasses the boot abort, enabling rule-based keyword matching and SQLite FTS5 BM25 rank ordering fallback across `Jev.system_one`, `balabot.growth.classify`, and `check_jev_health`, allowing offline and local operation without silent degradation when in standard mode.
- Persist inter-bot handoff notifications to durable SQLite queue: `balabot/handoffs.py` previously stored pending handoff frames in an in-memory dictionary (`_pending_handoffs`), which were lost whenever `bot_tools.message_agent` ran in a standalone CLI or tool subprocess, causing `drain_handoff_frames` in the server or subsequent processes to return empty; handoff frames are now persisted to a durable SQLite database (`BALABOT_HANDOFFS_DB` or `<BALABOT_DATA_ROOT>/handoffs/handoffs.db`), ensuring inter-bot notifications reliably survive process boundaries and restarts.
- Fix database path override bug in `_SESSIONS_PATCH_SNIPPET`: line 2911 of `ui/server.py` hardcoded `DEFAULT_DB_PATH` instead of using the resolved `db` variable read from `BALABOT_CONTINUITY_DB`, causing `PATCH /api/sessions/{session_id}` to fail with 404 or corrupt split databases under custom continuity DB configurations.
- Prevent event loop blocking during container execution in `_org_run`: long-running container snippets in `_org_run` previously ran synchronously via `subprocess.run` inside `async def` FastAPI route handlers (`/api/org/secrets`, `/api/groups/{gid}/turn`, `/api/sessions`), locking the asyncio event loop and freezing concurrent user requests and streaming SSE sessions; route handlers now dispatch via non-blocking `_org_run_async` using `asyncio.to_thread` while preserving synchronous compatibility for existing test fixtures and callers.
- Enforce 10 MiB bounded uploads and ingest image attachments as multimodal vision objects: `/api/attachments` previously accepted unbounded upload streams into memory risking server denial-of-service, and `/api/chat` formatted attachments as plaintext filename strings so vision models never received image data; uploads now enforce `ATTACHMENT_MAX_BYTES` (10 MiB limit, returning 413 on oversized uploads) with ReDoS-safe decoding, and image attachments (`image/png`, `image/jpeg`, `image/webp`, `image/gif`) are converted to OpenAI-standard multimodal `image_url` content objects in chat payloads.
- Encrypt secrets at rest with AES-256-GCM, discontinue shell environment variable injection, and add server-side `secret_request` proxy tool: secrets were previously stored in plaintext on disk and injected into the bot's shell environment as raw environment variables where prompt injection or `env` could exfiltrate them; secret values are now authenticated and encrypted at rest with record binding (`BALABOT_SECRETS_KEY` / `master.key`), legacy plaintext secrets are transparently encrypted in place on read/migration, raw environment injection is eliminated, and agents access external credentials via the server-side `secret_request` proxy with origin allowlist validation, SSRF blocking, redirect refusal, credential response redaction, and an audit trail.
- Persist intervention records and frames in durable SQLite store and block in `request_intervention`: intervention state and frames were previously kept in ephemeral in-memory dictionaries that were lost upon CLI subprocess exit without pausing the agent turn; records and frames now persist to SQLite (`BALABOT_INTERVENTIONS_DB`), `/api/interventions` reads durable state, and `request_intervention` blocks in a polling wait-loop until human resolution or timeout.
- Enable Agent Computer endpoints for dynamic fleet bots: `/api/computer/{bot_id}/frame`, `/action`, and `/reset` previously validated against hardcoded `PROFILES = ["principal", "governor"]`, returning an unavailable error for user-created bots; they now validate against the dynamic fleet helper `_all_bot_meta()` shared across the server.
- Inject queued in-flight messages into upstream chat completions payload in `/api/chat`: messages enqueued during active turns were drained into SSE frames but omitted from `messages` sent to the model, dropping user input sent while an agent was busy.
- Update `ThinkingBlock` and `ThinkingOrb` components to dynamically track active theme mode rather than pinning dark styling.
- Remove the seeded demo conversation from `ui/src/sessions.ts`: a hardcoded "hire a marketing and SEO expert" exchange with a fabricated OpenUI card appeared in every install with an empty session store. An empty store now yields an empty roster — a conversation exists only because an agent or the owner actually had one.
- Correct the OpenUI approve handler's error path in `ui/src/App.tsx`, which reported `Proposal created: <error>` — success wording on a failure.
- Make the Astryx theme's token pairs genuinely mode-aware in `ui/src/theme.ts`: every `[light, dark]` pair previously held the dark value in both slots, so Astryx-styled components stayed near-black in light mode while the CSS layer switched. Light entries now mirror the `light-dark()` values already declared in `balabot.css`, reconciling the two theme systems.
- Replace five references to undefined CSS custom properties in `ui/src/App.tsx` and `ui/src/Composer.tsx` (`--surface-default`, `--border-default` ×2, `--surface-sunken` ×2). Each silently fell back to a hardcoded dark value, which painted the transcript header bar solid black and washed out the composer and textarea surfaces once light mode could be reached; they now use the real `--card`, `--border`, and `--muted` tokens.
- Require an explicit chat confirmation before an agent files a bot proposal: `personas/principal/AGENTS.md` and `personas/governor/AGENTS.md` previously instructed agents to file immediately, which is why a request to hire an agent produced a proposal with no name, role or confirmation settled in the conversation.
