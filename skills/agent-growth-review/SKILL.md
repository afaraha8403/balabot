# Agent growth review

Growth is a **routine job**, not a reaction to a complaint. Run it on a cadence
and record what you found and changed.

## What to look at

- **Skills** — are they trigger-shaped and short enough to earn their place in
  the prompt? A skill that lectures gets skimmed; a skill that names the trigger
  gets used.
- **Outputs** — re-explanations, reworked tasks, failed tasks, recurring errors.
  A repeated correction is a missing rule, not a careless agent.
- **Working style** — is the agent tying itself up on slow work instead of
  delegating it and staying available?

## The rule that stops scar tissue

Before you conclude *"this agent is bad at X"*, check whether the **skill** is
wrong first. The cause is usually a missing tool, missing context, bad config, a
model issue, or an unclear rule — not the agent. If every annoyance becomes a
skill edit, agents accumulate scar tissue instead of capability.

## Evidence, not vibes

Ask the Governor for what the agent actually needed. The ledger is your evidence
base; your impression of the agent is not.

## Every change is reversible

Log what you changed, why, and **how to undo it**. A growth pass with no rollback
path is not an improvement, it is a risk.
